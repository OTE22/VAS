# Search UI improvements — 2026-09-21

The existing search workspace is preserved, with targeted improvements to result review and identity details.

- A persistent result overview distinguishes returned matches from distinct identities, faces/images, and watchlist alerts. Repeated appearances of one person do not inflate the distinct-person count.
- The overview records the submitted file, scope, depth, camera, date range, watchlist option and whether exclusions were applied. Editing controls after a completed search does not relabel its results. Batch mode clearly states that camera/date restrictions are not applied.
- Failed repeat searches retain prior results with an explicit notice that they belong to the previous successful search.
- Match cards label similarity and its server-provided band, detection counts, last seen, and the detail action. Explanatory text distinguishes similarity from confirmed identification.
- Identity detail styling now organizes the photo, badges, facts, match information, watchlists and sightings. Local badge positioning avoids the shared thumbnail style overlapping the close control.
- Camera UUIDs use configured names; unnamed UUIDs show “Camera name unavailable”. Named pipeline IDs remain valid human-readable fallbacks.
- Failed membership requests show unavailable status rather than falsely claiming no watchlist membership. Detail navigation links remain hidden until the requested profile loads.
- No backend storage, search model, scoring thresholds or enrollment behavior changed. No migration is required.
